# #29 — Resultado estruturado e importância Birnbaum

**Baseline:** `5f1169127d32b8af5ab9321a8dc3d16b73fdd514`

## Abordagem

Foi adicionada a função pública `analyze`, que compila a árvore e produz um
resultado estruturado sem alterar `build` nem `compute_event_probabilities`.
O resultado contém `Q` do evento de topo, probabilidades condicionais por
evento básico e Birnbaum. O mesmo formato está disponível na API em `result`
e na CLI por `--structured`, que emite JSON válido.

## Decisões

- `conditional_Q[id].true` e `.false` significam `Q` com o evento básico
  forçado, e não a probabilidade conjunta com o evento.
- Birnbaum é `Q|true - Q|false`, com sinal preservado. Isso é necessário para
  XOR e demais estruturas não monotônicas: um evento pode ter importância
  negativa.
- `assumptions` torna explícitos independência dos eventos básicos, ordem de
  variáveis do BDD, versão do pacote, seed, operação de shuffle/resampling,
  alinhamento das amostras e modo de confiabilidade.
- A API conserva `expression`, `symbolic`, `probabilities` e
  `top_event_probability`; o campo novo é aditivo.

## Evidência

- Uma árvore XOR de três eventos é confrontada com enumeração completa das
  oito atribuições. Ela valida `Q`, ambos os condicionais e Birnbaum assinado
  (`a = -0,04`).
- A CLI é verificada como JSON parseável com `--structured`.
- A API é verificada para os campos legados e `result` aninhado.
- `.venv/bin/python -m pytest -q` — 71 testes passaram, 25 subtestes; há um
  aviso de depreciação originado por `fastapi.testclient`/httpx.

## Limites e próximos passos

As probabilidades condicionais assumem a independência já declarada pelo
motor. Modelos com dependências comuns continuam exigindo representação
explícita na árvore. Medidas adicionais (criticality, FV, RAW e RRW) podem
usar a mesma compilação posteriormente.
